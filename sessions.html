  Project Abstract (about 190 words)

  Travelers often keep their day-by-day plans scattered across notes apps,
  spreadsheets and chat threads, which makes an itinerary hard to organize,
  share or use while traveling. PlanMyTrip is a responsive web application that
  brings this planning into one place. A traveler creates a trip of up to 14
  days, fills each day with activities, discovers things to do through an in-app
  ideas panel backed by Google Maps results, sees the weather forecast on each
  day, shares a read-only link with companions, and downloads the full itinerary
  as a PDF.

  The system is a React 19 and TypeScript single-page application with a layered
  FastAPI (Python) REST API and a PostgreSQL database hosted on Neon. Both are
  deployed together on Vercel as static files and serverless functions. Security
  is based on server-side sessions in httpOnly cookies, Argon2id password
  hashing, CSRF protection and per-user ownership checks. The project followed a
  spec-first process: requirements, frontend, backend and API-contract
  specifications were written before the code, and every feature was reviewed on
  a preview deployment with its own database branch before being merged through
  a pull request. The application is live in production and runs entirely on
  free tiers, at no running cost.

  Project Summary (about 230 words)

  PlanMyTrip is a full-stack trip planner, live at
  https://planmytrip-sur.vercel.app.

  Features delivered (13): user accounts; creating trips of up to 14 days with a
  trip type (solo, couple, family, friends); a list of my trips; a day-by-day
  plan with activities, times and notes; PDF export of the itinerary; safe
  editing and deleting of trips; a responsive design for phone, tablet and
  laptop; an ideas panel showing Google Maps places by category that can be
  added to any day; Google Maps links on every activity; an About page; back
  navigation; a weather forecast on each day (high, low and chance of rain in
  Celsius); and a read-only share link that anyone can open without an account.

  Technology: React 19, TypeScript, Vite, Tailwind CSS, TanStack Query and React
  Router on the frontend; FastAPI, Pydantic, SQLAlchemy and Alembic on Python
  3.14 for the backend; PostgreSQL on Neon; Vercel hosting; SerpApi and
  Open-Meteo for ideas and weather.

  Key decisions and challenges: one Vercel project for both frontend and backend
  (one domain, no CORS); cookie-based sessions instead of JWTs for security;
  database migrations that run automatically during each deployment; a 30-day
  shared cache and per-user daily limit to stay within the free
  250-searches-a-month quota; and an AI assistant that was designed but set
  aside to keep running costs at zero.

  Results: 9 pages, 17 API endpoints, 5 database tables and 88 passing frontend
  tests, at $0 per month. Next steps include automated testing in CI, login rate
  limiting and end-to-end tests.
