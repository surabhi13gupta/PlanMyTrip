The app in one page

From specs/goal-spec.md, now built.

Problem: travelers scatter day-by-day plans across notes apps, spreadsheets and chats. PlanMyTrip gives them one place to plan a trip day by day and print a clean itinerary.

What a user can do

  • Sign up and log in with a username and password
  • Add a trip: From and To dates, a destination, and a Trip Type (Solo, Couple, Family, Friends)
  • See all their trips on the home screen
  • Plan each day (Day 1 … Day N): add, edit, delete activities with a title, optional time and notes
  • Print the itinerary as a PDF; edit or delete a trip

Rules that shape everything

  • A trip is at most 14 days and can't start in the past
  • Activities belong to a day number, so they move with the trip's dates
  • Shortening a trip warns before deleting activities on removed days
  • Closing the page logs you out; unsaved edits are saved first
  • Users only ever see their own trips

Why a contract?

The frontend is TypeScript and the backend is Python, so they can't share code. Both follow api-contract-spec.md exactly: the same field names, rules, and error messages appear in frontend/src/lib/schemas.ts (Zod) and backend/app/schemas/ (Pydantic).

One request, start to finish

What happens when you type “Visit the Louvre” on Day 2 and click Save. Every feature follows this same path.

  1. Form · ActivityForm.tsx

    React Hook Form checks the values with the Zod activitySchema: title required, time like 09:30, notes up to 500 characters. Errors show under each field.

  2. Data hook · useTrips.ts

    useActivityMutations().add calls tripsApi.addActivity with { dayNumber: 2, title, time, notes }.

  3. API client · client.ts

    fetch('/api/v1/trips/<id>/activities') with Content-Type: application/json. The browser attaches the session cookie by itself.

  4. Proxy / routing

    Locally Vite forwards /api to port 8000; on Vercel, vercel.json sends it to the backend service.

  5. Middleware · middleware.py

    Logs the request and checks it's JSON, otherwise 415 (CSRF protection).

  6. Router · routers/activities.py

    Pydantic validates the body against ActivityCreateIn (trims text, rejects unknown fields). CurrentUser looks up the session from the cookie, or answers 401.

  7. Service · activity_service.py

    Loads the trip only if it belongs to this user (else 404), checks Day 2 is within the trip, saves the activity.

  8. Database

    SQLAlchemy inserts a row into activities; the response is the new activity as JSON, with time as "09:00".

  9. Back in the browser

    TanStack Query refetches the trip, the form closes, and the activity appears in Day 2 in time order.

How the key features work

The behaviour that took the most decisions, explained in plain words.

Logging in

Signup stores the password only as an Argon2id hash. Login creates a random token: the browser keeps it in an httpOnly cookie (page scripts can't read it), and the database keeps only a SHA-256 hash of it. Each request looks the hash up in sessions.

services/session_service.py

Logged out when the page closes

After login the tab stores a marker in sessionStorage, which survives refresh but is wiped when the tab closes. On start-up: no marker → call logout and show the login page; marker → ask the server who is logged in. Sessions also end after 12 idle hours.

lib/tabSession.ts · hooks/useAuth.ts

Saving the last edit on close

Each open form registers “what I'd send if the page closed now”. On the browser's pagehide event, every valid pending form is sent with fetch(…, {keepalive: true}), which finishes even after the page is gone. A change that would delete activities is never auto-saved.

lib/unsavedForms.ts · ActivityForm.tsx · TripForm.tsx

Shortening a trip

The Edit page counts activities on days past the new length. If any, it asks first, then sends confirmDeleteActivities: true. The backend refuses without that flag (409), and deletes plus updates in one transaction, so nothing is half-done.

pages/EditTripPage.tsx · services/trip_service.py

Only your own trips

Every trip query includes “and belongs to the logged-in user”. Someone else's trip looks exactly like a missing one (404), so IDs can't be probed. A test tries all 7 endpoints as another user.

tests/test_ownership.py

Print

Clicking Print loads the PDF library (about 445 KB) only then, builds the itinerary with Fira Sans and the app's dark blue, and downloads Paris-France-2026-10-10-itinerary.pdf.

Code walkthrough

Open each file to see the important part and what it does.

backend/app/models/trip.py: tables as Python classes 
class Trip(UUIDPrimaryKey, Timestamps, Base):
    __tablename__ = "trips"
    __table_args__ = (
        CheckConstraint("end_date >= start_date", name="trips_end_after_start"),
        CheckConstraint(f"end_date - start_date <= {MAX_TRIP_DAYS - 1}", name="trips_max_length"),
        …
    )
    activities: Mapped[list[Activity]] = relationship(
        cascade="all, delete-orphan", passive_deletes=True, order_by=…)

    @property
    def duration_days(self) -> int:
        return (self.end_date - self.start_date).days + 1

Each class is a table. The CheckConstraints make the database itself refuse a trip longer than 14 days, even if the code had a bug. cascade deletes a trip's activities with it (a test caught this missing at first). alembic revision --autogenerate turns changes here into migration files.

backend/app/services/trip_service.py: the shortening rule 
new_duration = (new_end - new_start).days + 1
removed = db.scalar(select(func.count()).select_from(Activity)
    .where(Activity.trip_id == trip.id, Activity.day_number > new_duration))
if removed and not data.confirm_delete_activities:
    raise ApiError(409, "ACTIVITIES_WOULD_BE_DELETED", …,
                   [{"activitiesToDelete": removed, "newDurationDays": new_duration}])
if removed:
    db.execute(delete(Activity).where(…, Activity.day_number > new_duration))
…
db.commit()  # the trip change and any activity deletion succeed or fail together

Because activities are tied to day numbers, only a shorter trip removes any. Moving the dates keeps the plan intact.

backend/app/services/session_service.py: sessions and the idle timeout 
def user_for_token(db, token):
    session = db.get(UserSession, hash_token(token))
    if session is None: return None
    if session.expires_at <= now:            # 12 idle hours passed
        db.delete(session); db.commit(); return None
    if session.expires_at - now < _idle() - RENEW_MARGIN:
        session.expires_at = now + _idle()  # renewed at most once an hour
        db.commit()
    return session.user

Used by deps.get_current_user, which every protected endpoint depends on. Logout deletes the row, so the token stops working immediately.

backend/app/middleware.py and errors.py: safety nets

RequireJsonMiddleware rejects any POST, PATCH or DELETE to /api/ that isn't JSON with 415. A form on another website can't send JSON, so it can't trick your browser into changing your trips (CSRF).

install_error_handlers turns every failure into the contract's shape {"error": {"code", "message", "details"}}: validation errors become 400 with one entry per field, unknown pages 404, a down database 503, and anything unexpected 500 without leaking details.

frontend/src/api/client.ts: the one place that talks to the backend 
headers: method === 'GET' ? undefined : { 'Content-Type': 'application/json' },
…
if (!response.ok) {
  throw new ApiError(response.status, error?.code ?? 'HTTP_ERROR', error?.message ?? …, details)
}

Every non-2xx answer becomes an ApiError with the contract's code, so pages can react precisely: USERNAME_TAKEN under the username field, ACTIVITIES_WOULD_BE_DELETED reopens the warning, UNAUTHORIZED sends you to login (queryClient.ts).

frontend/src/hooks/useAuth.ts: start-up session check 
export async function loadSession() {
  if (!hasTabLogin()) {                 // fresh visit after the page closed, or a new tab
    await authApi.logout().catch(() => {})
    return null
  }
  try { return await authApi.me() }     // a refresh: still logged in?
  catch (error) { if (401) { clearTabLogin(); return null } throw error }
}

The result lives in the ['me'] query. AppShell (router.tsx) shows a spinner until it's known, then ProtectedRoute and PublicOnlyRoute decide where you may go.

frontend/src/components/DayCard.tsx: one day of the plan

Shows “Day N” and its date, the day's activities sorted by activitiesForDay (timed first, then in the order added), an inline ActivityForm for adding or editing, and a ConfirmDialog before deleting. Each form passes toPendingSave, the request to send if the page closes before Save.

frontend/src/lib/schemas.ts: the contract's rules in Zod 
if (v.startDate !== originalStartDate && v.startDate < today) → "The start date can't be in the past."
if (v.endDate < v.startDate)                               → "The end date can't be before the start date."
else if (getTripDuration(v.startDate, v.endDate) > 14)     → "A trip can be at most 14 days long."

Same rules and messages as the backend's Pydantic models. When editing, a trip that already started can keep its past start date.

Glossary

Technical terms used in this guide and the specs. Product terms (Trip, Day, Activity) are in the goal spec's glossary.

TermMeaning
API / endpointThe URLs the backend answers, like POST /api/v1/trips. One URL plus method is an endpoint.
JSONThe text format for data sent between frontend and backend: {"status": "ok"}.
HTTP statusA number with each response: 200 ok, 201 created, 204 done (no body), 400 bad input, 401 not logged in, 404 not found, 409 conflict, 415 wrong format, 503 unavailable.
ProxySomething that forwards requests elsewhere. Vite's proxy forwards /api to port 8000.
Environment variableA setting given from outside the code, such as DATABASE_URL. Keeps secrets out of git.
MigrationA versioned script that creates or changes tables, applied in order by Alembic.
ORMA library (SQLAlchemy) that lets Python work with rows as objects.
TransactionA group of database changes that all succeed or all fail together.
HashA one-way scramble: easy to compute, impossible to reverse. Used for passwords (Argon2id) and session tokens (SHA-256).
Session cookieA small value the browser sends automatically to prove you're logged in. httpOnly means page scripts can't read it.
sessionStorageBrowser storage that belongs to one tab: kept on refresh, wiped when the tab closes.
CSRFAnother website tricking your browser into sending a request to ours. Blocked by SameSite=Lax and JSON-only writes.
XSSSomeone's script running on our page. React shows text as text, and the cookie is out of scripts' reach anyway.
ContainerA sealed, disposable box running one program (here PostgreSQL), managed by Docker.
Virtual environment / lock fileA private folder of Python packages (.venv), and the exact versions of every package (uv.lock, package-lock.json).
Serverless functionCode the host starts only when a request arrives. The backend runs this way on Vercel.
Preview deploymentA temporary copy of the app for each branch, with its own URL and database copy.
Mock (MSW)A stand-in for the real backend during tests, answering with fixed data.
LintAutomatic checks for likely bugs and style problems (ruff, oxlint).
Dependency injectionFastAPI's Depends(...): it prepares what a function needs (database session, current user) and passes it in.
